# Documentation standard

Useful, accurate, maintainable — not long for its own sake.

When documenting a system/feature, prefer: Overview · Purpose · Scope · Architecture · Responsibilities · Data flow · API · Dependencies · Config · Security · Performance · Errors · Testing · Deploy · Limitations.

Product PRs: code + tests only. Reviewer handoffs and screenshots go **on the PR**, not in the merge tree  (keep review handoffs out of merge trees when that is team policy).
